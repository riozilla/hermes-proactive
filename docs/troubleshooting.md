# Troubleshooting

| Symptom | Check | Corrective approach |
|---|---|---|
| Still waits for every instruction | Accepted outcomes, runnable next step, private preparation authority | Clarify ownership and useful action, not just adjectives |
| Sends summaries but does no work | Full job prompt and operating skill actually loaded | Require a verified artifact or resolved small blocker |
| Duplicates alerts | Shared delivery keys, leases, resolved-item checks, existing overlapping jobs | Consolidate; use source versions and one delivery route |
| Misses an unchanged approaching event | Time-window and next_check_at triggers | Wake for elapsed time, not only source changes |
| Says nothing while an integration is broken | Source freshness, real run evidence, authentication | Mark degraded coverage and provide bounded recovery |
| You cannot reply meaningfully to a brief | Continuation supported and tested for actual target | Configure per-job continuation; test the user's reply |
| Too many tokens or slow chat | Gates, tool schema size, bounded work, model saturation | Use tested cheap gates or slower fallback; reserve foreground capacity |
| Runs at the wrong time | Effective profile, IANA timezone, environment, upcoming scheduler times | Resolve locally; test daylight-saving transitions |
| Claims completion but result is inaccessible | Artifact access, send evidence, execution versus delivery state | Verify each stage separately |
| No notice during total gateway outage | Independent monitoring | Do not rely on a stopped gateway to report its own failure |

Do not debug by exporting the full profile, environment, transcripts, or credentials into a public issue. Use a minimal synthetic reproduction and describe the capability gap. A failed read is unknown coverage, not an empty inbox.
